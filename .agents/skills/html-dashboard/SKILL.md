# Interactive A2UI Dashboard & Web Generator Skill

This skill guides the AI Agent in producing interactive, dark-themed, publication-grade visual financial dashboards on-demand.

The web architecture is powered by a **Declarative A2UI (Agent-to-UI)** system:
- **Agent Role (Producer)**: Inspects deliverables in `data/output/` and emits a declarative `data/output/ui_manifest.json`.
- **Web App Role (Consumer / Renderer)**: A generic, zero-hardcoding Vue 3 + DaisyUI + Hono fullstack app (`web/`) that dynamically mounts KPIs, Charts, DataTables (with cross-account asset aggregation), Key-Value progress lists, and Markdown docs with native Mermaid support.

---

## 1. Core Operating Principles

1. **On-Demand / Opt-In Only**:
   - Web dashboards are **never generated by default**. Standard runs only produce deterministic Markdown reports (`data/output/<name>_report.md`) and structured CSV files (`data/output/<name>.csv`).
   - Only activate this skill when the user explicitly requests an HTML report, web view, or visual dashboard.
2. **Dynamic & Schema-Driven (A2UI)**:
   - **Do NOT assume a fixed schema or fixed set of reports.** The session deliverables may represent Asset Allocation, Brinson Attribution, Retirement Monte Carlo Projections, Cash Flow Budgeting, Tax Optimization, or Real Estate models.
   - The Agent declares what KPIs, Tabs, Charts, and Tables make sense for the current run via `ui_manifest.json`.
3. **Zero Absolute Paths**:
   - Never embed system root paths or file URI schemes in any output manifest or HTML.

### Supported Widget Types:
- **`chart`**: `chartType: 'donut' | 'bar' | 'horizontal-bar' | 'line'` with `labels` and `datasets`.
- **`data-table`**: `sourceCsv` (or inline `rows`), `columns` with formats (`currency`, `percent`, `number`, `badge`, `text`), and `features` (`aggregateBy: 'symbol'` for cross-account consolidation, `search`, `filters`, `exportCsv`).
- **`markdown`**: `sourceMd` (or inline `content`) with native Mermaid diagram rendering & copy button.
- **`key-val-list`**: List of progress bar items (`label`, `value`, `progressPct`, `color`).

## 3. Step-by-Step Generation SOP

When user requests the web report / dashboard:

### Step 1: Inspect Session Outputs
Check what files currently exist in `data/output/`:
- CSV deliverables: `data/output/*.csv`
- Markdown reports: `data/output/*.md`

### Step 2: Write Ad-Hoc Generator in `data/tmp/generate_ui_manifest.py`
Write a Python script that reads the generated CSVs and metrics, computes summary aggregations, and writes `data/output/ui_manifest.json`.

```python
import json
import csv
from pathlib import Path

output_dir = Path("data/output")
# 1. Ingest CSVs & compute metrics
...
# 2. Build declarative manifest dictionary
manifest = {"schemaVersion": "1.0", "title": "...", "kpis": [...], "tabs": [...]}
# 3. Save to data/output/ui_manifest.json
with open(output_dir / "ui_manifest.json", "w", encoding="utf-8") as f:
  json.dump(manifest, f, indent=2)
```

### Step 3: Execute the Script
Run using `uv`:
```bash
uv run python data/tmp/generate_ui_manifest.py
```

### Step 4: Verify & Notify User
1. Verify `data/output/ui_manifest.json` was created cleanly with valid JSON.
2. Inform the user they can view the dashboard by running:
   - `just dev` (Dev mode: Hono API on `:3000` + Vite UI on `:5173`)
   - `just serve` (Production mode: Hono API + UI on `:3000`)
